# 电子税务局版本发布 · 连续判定引擎（release_guard）

在灰度发布过程中**边看边判定**新版本好坏的纯 Python + NumPy 引擎。解决传统
「固定样本量检验 + 反复偷看大盘」在连续观察下误报率失控、且看不出单人群
局部劣化的问题。

## 七项需求如何落地

| # | 需求 | 实现 |
|---|------|------|
| 1 | 连续观察、任停时刻误报率受控 | 全部统计量是 **e-process**（超鞅）。Ville 不等式保证 `P(任停时刻 E≥1/α) ≤ α`，每批都能下结论而不累积偷看偏差。比例类用精确 beta-二项 e-process（`TwoSampleBernoulliE`），均值类用 mSPRT（`eprocess.py`） |
| 2 | 不同指标类型用合适统计量 | 成功率→伯努利失败率；长尾时延→超过发布前 p95/p99 阈值的超标率（分布无关的分位数代理）；每用户请求数→计数强度。统一成「每用户一个标量」后进入检验（`metrics.py`） |
| 3 | 多指标 × 多细分的多重性校正 | 回滚门限用**层级 Bonferroni e 门限**（全局 M/α、切片 2MK/α），保证 FWER≤α；另用 **e-BH** 在 FDR 水平给出细分定位短名单，避免校正到什么都查不出 |
| 4 | 先验随机化有效性 | SRM 检查：在**随机化单位（去重用户）**上用时变零假设的 Jeffreys e-process 对照爬坡意图比例；另有对照组 vs 发布前基线的漂移检查 |
| 5 | 同用户多次请求不独立 | 一切先按用户聚合，独立抽样单位是**用户**而非请求；保留 `naive_request_level` 反模式开关用于对比低估方差 |
| 6 | 三态结论 + 效应区间 + 超时最坏值 | GO / ROLLBACK / CONTINUE；每次输出始终有效的置信序列与单侧有害上界；观察期用完仍不收敛时报告「当前最坏可能劣化」 |
| 7 | 流量比例随把握与损失调整 | `RampController` 自适应策略：归一化风险 × 剩余安全预算决定下一批增长倍率，无回滚信号时持续爬升、有信号时停滞/归零；另保留固定阶梯策略做对照 |

## 目录

```
release_guard/
  eprocess.py    e-process、置信序列、精确伯努利检验、SRM 序贯检验
  metrics.py     三类指标定义与实际效应地板
  engine.py      流式判定引擎（用户聚合、多重性、三态、SRM/基线）
  ramp.py        自适应 / 固定阶梯流量控制器
  generator.py   可埋各种幅度形态劣化的流量生成器 + 发布前基线
  dashboard.py   现行大盘固定阈值规则（对照），含 z 分数校准版
  simulation.py  数千次模拟发布的验收框架与汇总
  viz.py         纯 Python 生成自包含 HTML+SVG 判定轨迹页面
  tests.py       无第三方依赖的单元测试（python3 -m release_guard.tests）
```

## 统计保证的关键点

- **为什么不用普通 t 检验/卡方反复看**：固定样本检验在 K 次偷看下误报率随 K
  无界增长。e-process 的超鞅性质把「任意停止时刻」的越界概率整体压在 α 内。
- **为什么比例指标不用渐近 mSPRT**：1% 量级稀疏伯努利在小样本下正态渐近反保守
  （实测单看 e 值可飙到上千）。`TwoSampleBernoulliE` 用 Jeffreys beta-二项
  边际似然比，零假设模拟下 `P(E>100) ≤ 0.6%`，在任意样本量都合法。
- **置信序列**：mSPRT 混合先验下各分量的接受域是解析二次区间，取交集即得，
  无需逐点二分；单侧有害上界由双侧 CS 上端点派生。
- **切片只拦回滚、不拦放行**：小切片区间天然宽，要求所有切片都收敛会让 GO
  不可达。GO 只看全局实际地板，局部劣化由切片回滚门负责。

## 验收方法

```bash
python3 -m release_guard.tests           # 统计保证与引擎机制单测
python3 -m release_guard.demo            # 生成两个 HTML 判定轨迹页面
python3 -m release_guard.clustering_demo # 需求5：用户内相关如何抬高误拒绝率
python3 -m release_guard.ramp_compare    # 需求7：自适应 vs 固定阶梯爬坡
# 完整网格（干净 400 次 + 各幅度/形态/细分场景，约 2500 次发布）
python3 -c "from release_guard.simulation import run_validation; \
  run_validation('outputs/full_grid')"
# 汇总成 Markdown 验收报告
python3 -m release_guard.report outputs/full_grid/validation_report.json
```

`clustering_demo` 是一个不经过引擎的受控实验（避免被精确伯努利检验掩盖）：
同一零假设数据分别按「请求级」和「用户级」做两样本 z 检验。在较强用户内
相关下，请求级名义 5% 的检验实际误拒绝率约 16%，而用户级保持在 5% 左右——
直接量化了把请求当独立样本的危害。

`ramp_compare` 在相同引擎、相同数据流上对比两种爬坡策略（各 120 次/场景）：

- 干净发布：两者误回滚率相同（约 0.8%），自适应平均 26.8 批收敛、固定阶梯 29.3 批；
- 故障发布：自适应决策更早、爆炸半径更小。例如时延突发场景自适应回滚时中位
  波及约 3061 个处理组请求，固定阶梯约 4840 个；+1pp 失败率场景自适应 4.8 批、
  阶梯 5.3 批。自适应在无信号时持续爬升以积累证据，在有信号时立刻停滞/归零。

验收关注：干净版本误回滚率是否 ≤ 声明 α；各劣化幅度的检出率与回滚时已波及
的请求数；仅单人群劣化的检出与定位率；以及与大盘固定阈值规则的头对头对比。

## 可视化页面

`viz.py` 输出单文件 HTML（内联 SVG，无外部依赖），逐指标展示 e-process 如何
逼近回滚门限、置信序列如何随批次收窄、爬坡比例与 SRM 曲线，以及细分格子
e 值热力图——局部劣化会呈现为单独一行变红而全局保持平静。
